packitless

Machine-generated text is mostly repetition, and you pay full token price for every copy of it. This page is every number the tool produced, including the ones that make it look worse.

Why it works

Two thousand HDFS log lines, zero of them exact duplicates — so deduplication saves nothing. Under templating they collapse to a handful of shapes. Each block below is one template, sized by how many lines it covers.

Does compression hurt the answer?

    
Log summaries scored 1–5 by an independent LLM judge that always sees the
    uncompressed logs as ground truth, so a summary that lost something real has nowhere
    to hide. Eight incidents, 48 runs.

    
    

      
Read this honestly: quality is not monotonic — a 200-token payload scored
      higher than an 800-token one. At n=8 on an integer rubric those gaps are noise. The
      defensible claim is “no detectable quality loss down to 200 tokens”, not “we found the optimum”.

    

  


  

    
Fidelity, measured for free

    
An LLM judge costs money and returns a noisy integer. Whether compression discarded
    something is deterministic, and runs on every commit at zero cost. Note the row where a
    90%-saved headline is produced by throwing away 99.9% of the records — the token count alone
    calls that a triumph.

    

  


  

    
Where it applies — and where it declines

    
Extractor selection is a competition: each reports how well it expects to do, highest wins.
    Because that score is a compressibility estimate rather than format detection, prose and source
    code score near zero and pass through untouched instead of being mangled.

    
  


  

    
Logs it had never seen

    
Every number above comes from corpora used while building the tool, which is a weak claim
    about unseen data. These are real logs pulled off a laptop — Apple installer, WiFi driver, APFS
    check, a disc-recording daemon, a game client — with no tuning of any kind.

    
  


  

    
Dropped into a real service

    
Flare is a production log-triage service. It truncates each incident to
    log_lines[:50] to control cost — a budget expressed in rows, which is the wrong
    unit, since fifty verbose lines and fifty terse ones cost wildly different amounts.

    

    
Not just cheaper — better informed: the adapter reads
    every line and still spends a fraction of the tokens.

  


  

    
Try it on your own logs

    
Runs entirely in this page. Your logs are never uploaded, stored, or sent
    anywhere. Capped at 5,000 lines; a truncated sample understates compression, because fewer
    lines means fewer repeats.
