What it costs you in quality

    
Summaries scored by an independent LLM judge that always sees the uncompressed
    logs as ground truth, with every candidate for an incident rated side by side in one call —
    so a summary that dropped something real has nowhere to hide.

    
    

      
Read this honestly. At 94% compression the result ranks level with the
      uncompressed baseline — 4.17 against 4.08, standard deviation near 0.5 at n=8. That is a
      tie, not a win. Below roughly 800 tokens quality does degrade, and you can see it.

      
An earlier version of this experiment scored each summary alone rather than against its
      siblings, and reported the whole curve as flat noise. The instrument was the problem, not
      the compressor — worth saying out loud, because the first result was the flattering one.

    

  


  

    
When our own number is a lie

    
A compression ratio on its own is unfalsifiable — you can always hit any number by
    throwing data away. These checks are deterministic, need no API key, and run on every commit.
    The highlighted row is our own tool reporting a 90% saving it earned by discarding 99.9% of
    the records.

    

    
Critical recall is 1.000 in every row. Whatever
    the budget, records flagged as important survive verbatim — the allocator will overrun the
    budget rather than drop one, and it reports the overrun.

  


  

    
It also knows when to decline

    
Extractor selection is a competition, and the score is a compressibility estimate rather
    than format detection. Prose and source code score near zero, so they pass through
    byte-for-byte. It will never hand you back more tokens than you gave it.
